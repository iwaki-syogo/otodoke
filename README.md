# Otodoke（おとどけ）

**注文メールを転送するだけで、「何がいつ届くか」「いつ家にいればいいか」「今月いくら使ったか」が分かる、自分のための荷物カレンダー。**

> Built with Claude: Japan 2026（2026-11-02 〜 11-08）の提出作品です。すべてのコードはイベント期間中に新規に書いています。

*English: Otodoke turns the order / shipping emails you already receive from any Japanese EC site into one parcel calendar: what is coming, when, whether someone must be home (no 置き配), and how much you spent this month. Built with Claude Code during Built with Claude: Japan 2026.*

## 課題

Amazon、楽天、メーカー直販、コンタクトレンズの通販。買い物の場所が増えるほど、

- 何を注文したか忘れる
- 発送されたのか、いつ届くのか分からない
- 置き配できない荷物の「家にいる日」を覚えていられず、不在票が溜まる
- 今月オンラインでいくら使ったか分からない

宅配便の再配達率は 2026 年 4 月のサンプル調査で 7.6%（国土交通省）。受け取る側が「いつ届くか」を把握できないことが、その一因です。

## 仕組み

1. 登録すると、あなた専用の受信アドレスが発行されます
2. 自分のメール（Gmail / iCloud / Outlook など）で、そのアドレスへの自動転送を **1 回だけ**設定します
3. あとは何もしません。届いた注文・発送・配達メールを Claude が読み、荷物ごとに整理します
   - 店・注文番号・品目・金額・状態（注文中 / 発送済 / 配達済）
   - 配達予定日・時間帯・追跡番号・運送会社
   - 置き配できるか（できなければカードに印を付け、カレンダーではその日を赤くします）
4. 荷物カレンダー・一覧・今月の支出として表示します

抽出した値には、元メールのどの行が根拠かと確信度が必ず付きます。不確かなものは「要確認」になり、画面から元メールに戻れます。

## Claude をどう使ったか

**アプリの中で。** Claude が担うのは、店ごとに形式が違うメールの「判定」です。

- メールが注文・発送・配達・キャンセルのどれか、どの値が配達日か、置き配の案内が定型文か本当の指定かを読み分けます
- 出力は zod のスキーマで固定し、値ごとに根拠の行と確信度を持たせます。確信度が低い値は断定して表示しません
- 追跡番号から運送会社を決める処理はルールで書き、Claude には任せません
- 同じ荷物の名寄せは、注文番号・追跡番号・品目を使ってコードで行います

**費用を抑える仕組み。** メールが届くたびに読むと、利用者が増えるほど赤字になります。そこで 3 段階にしています。

1. 無料のルールで広告を落とします。店の許可リストは使わないので、知らない店で買っても動きます
2. 判断に迷うメールだけを Haiku に聞きます。API が失敗したらメールを残します
3. 残ったメールを読みます。1 人 1 日と全体 1 日の上限を DB で取ってから呼び出します

**モデルは実測で選びました。** 手で正解を付けたデモ 17 通の結果です。

| モデル | 項目の一致 | 17 通の費用 |
|---|---|---|
| Claude Opus 5.5 | 73/73 | $0.46 |
| Claude Sonnet 5.5 | 73/73 | $0.23 |
| Claude Haiku 5.5 | 71/73 | $0.02 |

Haiku の外れ 2 件は時間帯の書式の違いで、コード側で吸収しました。さらに匿名化した 341 通で種類の判定を確かめ、既定を Haiku にしました。項目の精度を確かめたのは 17 通だけです。記録は `docs/eval-log.md` にあります。デモボタンの結果は Opus 5.5 で事前に生成して保存したものです。

**開発で。** コードは Claude Code で書きました。`.claude/settings.json` の hooks で、force push、実メールのコミット、鍵を含むコミットを止めています。実メールのふるいを変えると `npm run check:screen` が走り、荷物のメールを 1 通でも落とすとコミットできません。

## 技術

- Next.js 16 / React 19 / TypeScript / Tailwind CSS v4

## 動かし方

**すぐ試す。** https://otodoke.app を開き、メールアドレスでログインします。設定画面の「サンプルのメールを読み込む」を押すと、匿名化したメール 17 通が今日の日付に合わせて読み込まれます。この操作では Claude API を呼びません。

**手元で動かす。** Node.js、Supabase のプロジェクト、Resend のアカウント、Claude API のキーが必要です。

```bash
npm install
cp .env.example .env.local   # 値を埋める
npx supabase db push         # スキーマを適用
npm run dev                  # http://localhost:3015
```

`npm test` は API を呼びません。`npm run eval` は Claude API を呼ぶので課金されます（`--max-usd` で上限を指定）。

## 持ち込んだデータ

`fixtures/demo/` のメール 17 通は、作者自身が受け取った実際の注文・配送メールから、氏名・住所・電話番号・メールアドレス・注文番号・追跡番号を差し替えたものです。イベント前から存在するデータの持ち込みとして、ここに明記します。コードはすべて期間中の新規制作です。

精度の評価には、同じ方法で匿名化した 341 通を手元で使っています。買い物の履歴そのものなので、公開するのはデモの 17 通だけです。匿名化の手順は `scripts/anonymize.py`、結果の数字は `docs/eval-log.md` にあります。
