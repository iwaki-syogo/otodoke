# メール項目マップ（店・運送会社ごとのメールの書式）

抽出器（`src/lib/extract/`）を作るための下調べ。店と運送会社の通知メールについて、
「どの項目が、どのメールの、どこに、どんな言い回しで書かれているか」と、読み取りでつまずく点をまとめた。

- 書いてあるのは**書式だけ**。金額・日付・時刻・番号・品名はすべて架空の値に置き換えてある
  （金額 `1,234円` / `￥1,234` / `1234 JPY`、日付 `2026/01/01` / `1月1日(木)`、時刻 `12:00`、番号は `N` で伏せた）
- 氏名は「山田太郎」、住所は「〒100-0001 東京都千代田区千代田1-1 サンプルマンション101」、電話は 090-0000-0000 の置き換え
- 「本文」は text/plain、「HTML」は text/html をテキスト化したもの
- 評価セット（匿名化した実メール、`fixtures/anonymized/`）は買い物の履歴なので公開していない。公開しているのはデモ用の `fixtures/demo/` だけ

## 配達予定が書かれていないメール

| 店・運送会社 / メール | 配達予定の有無 |
|---|---|
| Amazon / 配達済み・取消 | 無し（完了・取消なので不要） |
| Amazon / 定期おトク便「新しい定期おトク便のご登録」 | **本文には無く HTML にだけある**（`木曜日, 01/01までに到着予定`） |
| 楽天（order@ / ショップ） | 無し。order@ の `[お届け日時]` は空欄、メール便は日時指定不可 |
| OCN / 注文 | 日付は無く時間帯だけ（`【配送希望時間帯】18～21時` の形）。発送は日付も時間帯も無し |
| レンズアップル 全メール | 無し（発送も「近日中にお届け」） |
| アイリスプラザ / 発送 | 無し（「最短の配送予定にて出荷手配」） |
| GEKIROCK CLOTHING / 注文 | 無し（発送には `お届け日` `お届け時間` あり） |
| ユニクロ / 発送 | 無し（注文に `配送予定日：YYYY/MM/DD - YYYY/MM/DD`） |
| TikTok Shop / 発送 | 項目はあるが値が壊れている（`最新の配達予定` → `ll-+0900 - ll-+0900`） |
| ヤマト / 完了・不在・Myカレンダー | 無し（完了・不在・設定通知） |
| 佐川 / 完了・不在通知 | 無し |

## Amazon（amazon.co.jp）

送信元で段階が決まる: `auto-confirm@`＝注文、`shipment-tracking@`＝発送・配達中、`order-update@`＝配達済み・一部の取消、
`no-reply@`＝定期おトク便と定期の取消。Date ヘッダーは **すべて UTC（+0000）**。

| 項目 | 場所と書き方 |
|---|---|
| 注文番号 | 本文: `注文番号` の次の行に `NNN-NNNNNNN-NNNNNNN`。HTML では `注文番号 ‫NNN-…` と番号の直前に不可視の RTL 記号（U+202B）が入る。配達済みの一部は件名にも `注文番号 NNN-…` / `注文‎#NNN-…`（LRM 入り） |
| 品名・数量・価格 | 本文: `* 品名（省略なし）` / `  数量: 1` / `  1234 JPY`。HTML は品名が `...` で切れ、価格は `￥1,234`。配達中メールは価格なし |
| 合計 | 注文・発送メール: `合計` の次の行に `1234 JPY`（品目の価格はクーポン前・合計は値引き後で一致しないことがある） |
| 注文日 | 書かれていない（Date ヘッダーで代用） |
| 状態 | 冒頭の 1 行: `ご注文ありがとうございます。` / `荷物が発送されました。` / `荷物は配達中です。` / `荷物は配達済みです!`。その下の進捗表示（注文済み・発送済み・配達中・配達済み）は **どのメールにも 4 語とも並ぶ**ので状態の根拠にならない（HTML の `[完了済み]` / `[保留中]` 画像 alt で区別） |
| 配達予定 | 相対表現が中心: `本日到着予定` / `明日到着予定` / `木曜日にお届け` / `1月1日から1月5日までにお届け` / `1月1日にお届け` |
| 時間帯 | `明日5:00～13:00に到着予定` / `本日5:00～13:00に到着予定`（全角チルダ） |
| 運送会社・追跡番号 | **どのメールにも無い**（`配送状況を確認` のリンクだけ） |
| 置き配・受け取り方法 | 配達中メールには毎回 `荷物を残す場所を伝えたい場合は、 配送方法を追加してください` が入る（案内文で、指定の有無は分からない）。実際の受け取り方が書かれるのは配達済みメールの一部だけ（下記） |
| 取消 | `商品はキャンセルされました` / `注文はキャンセルされました。 この注文の請求は行われていません。`（`order-update@`）。定期は `お客様のサブスクリプションはキャンセルされました。` |
| 返金 | 書かれていない |

配達済みメールに受け取り方が書かれる場合は、本文の 1 文で書かれる（例: `…直接手渡しました。` / `…宅配ボックスに配達しました。`）。宅配ボックスの場合は、その下に番号などの行が続くことがある。

- たいていは `本日お届け済み` だけで、置き場所は書かれていない。配達写真は HTML の `<img src="https://jp-prod-temp.s3…">`（alt 無し・期限付き URL）にしかない
- 旧書式（本文が `山田太郎様` から始まり進捗表示が無い）もあり、その場合は件名がそのまま配達結果の文になる
- 新しい書式の配達済み（件名 `配達済み:1点の商品 | 注文番号 …`）は本文にも HTML にも品名が無い

件名の型（日付・時間帯は件名には出ない）:

```
注文済み: 「（品名）...」
発送済み：「…」とその他1商品 / 発送済み:2点の商品。 ご注文品は配達中です。
配達中:「…」とその他1点の商品
```

### 定期おトク便（`no-reply@`）

- 件名: `新しい定期おトク便のご登録` / `定期おトク便の商品が変更になりました。` / `次回の配送を確認する` / `価格の変更: 次回の配達をご確認ください`
- 配達予定は年が無く、書き方が揺れる: `木曜日, 01/01までに到着予定` / `木曜日, 1月 1までに到着予定` / `1件の定期おトク便が 木曜日, 01/01 に到着します。`
- 頻度（`Nか月ごと`）と初回の到着予定は「ご登録」メールでは HTML にだけある
- お届け先は `山田太郎に配達予定 千代田区千代田 1-1 サンプ...` のように住所付き（途中で切れている）

## Design notes for the extractor

### 確実に取れるもの（本文だけで足りる）

- **注文番号**: Amazon（`注文番号` 次行）、楽天、OCN、レンズアップル、アイリス、GEKIROCK、ユニクロ、TikTok。ラベルの後ろが「同じ行・コロン」「次の行」「区切り無し」「`=`」の 4 通りあるので、ラベル＋次の行までを見る
- **追跡番号**: 運送会社と店の発送メール。形は `N×12` か `NNNN-NNNN-NNNN`（ヤマト・日本郵便）。同じ荷物でもメールによって区切りの有無が変わるので、比較は数字だけにしてから行う。運送会社はラベルの近くに書いてある（`運送便` `配送会社` `【配送業者】` `■佐川急便`）か、送信元のドメインで決まる
- **配達予定日（運送会社）**: ヤマトは `【M月D日(曜) …】`、佐川は `YYYY/MM/DD（曜）`、日本郵便は `M月D日(曜)`。ヤマト・日本郵便は年が無いので、メールの日付から年を補う（年末年始は翌年に繰り上げ）
- **時間帯**: `時間帯希望なし` / `時間指定なし` / `午前中` / `18時～20時` / `19〜21時` / `19:00〜21:00` / `5:00～13:00`。区切りが `～`（全角チルダ）・`〜`（波ダッシュ）・`-` で揺れる
- **配達完了**: ヤマト `お届け完了日時`、佐川 `お届け完了日時`、Amazon は件名 `配達済み` と `本日お届け済み`
- **品名・数量・価格**: Amazon の注文・発送（本文の `* ` 行が省略なしの品名）、楽天 order@、OCN、レンズアップル、アイリス、GEKIROCK、TikTok

### HTML が要るもの

- Amazon 定期おトク便「ご登録」の到着予定と頻度（本文に無い）
- Amazon 配達済みの配達写真（`<img>` だけ）
- ヤマト「お荷物お届けのご案内」の `受取方法 ： ◯◯`、郵便受け通知の `置き配で受け取り可能です。`
- TikTok Shop は HTML だけで届く
- Amazon の状態は本文の冒頭 1 行で決まるが、進捗表示で決めたいなら HTML の `[完了済み]` / `[保留中]`
- 注意: HTML の Amazon 注文番号の前には U+202B、件名の `注文‎#` には U+200E が入る。正規表現の前に不可視文字（U+200B–U+200F、U+202A–U+202E、U+2066–U+2069、U+034F、U+00AD）を消す

### たいてい無いもの

- **Amazon の運送会社と追跡番号**（調べた範囲では一通も無い）。Amazon の荷物と運送会社のメールは注文番号では結べない。結ぶなら「運送会社メールの差出人が Amazon」「配達予定日が一致」「同じ日に配達中」の弱い手がかりしか無いので、`needs_review` にする
- **運送会社メールの注文番号・品名**（ヤマト・佐川・日本郵便には無い）。品名はヤマトの分類名だけ
- **配達予定の年**（ヤマト・日本郵便・Amazon 定期・アイリスの注文日）
- **Amazon の配達予定の絶対日付**。`本日` / `明日` / `木曜日` がほとんどで、メールの送信日時から計算する。Date は UTC なので **JST に直してから**「本日」を決める（夜遅く・朝早くのメールは UTC と JST で日付が変わる）
- **置き配の実際の指定**。「置き配できます」という案内文は多い（ヤマトのほぼ全通知、Amazon の配達中メール、佐川の定型文）が、実際に指定された受け取り方が書いてあるのは少ない:
  - Amazon: 配達済みメールの一部の `直接手渡しました` / `宅配ボックスに配達しました`
  - ヤマト: `（受取方法：◯◯）`、`■受取ご希望場所：◯◯`、`受取方法 ： ◯◯`
  - 佐川: `■配達指定場所`
  - 「置き配可能」「置き配指定可能」は指定ではないので、受け取り方の判定に使わない（`置き配` の語の有無だけで判定すると誤る）
- **返金**（金額付きの返金通知は見当たらない。Amazon 取消は `請求は行われていません`）
- **ショップの注文メールの配達予定**（楽天・レンズアップル・アイリス・OCN は無いか、時間帯だけ）

### 名寄せ（同じ荷物か）の手がかり

- 店内: 注文番号で 注文→発送→配達中→配達済み を結べる（評価セットでも偽番号は全メールで一貫させてある）
- 店→運送会社: 店の発送メールにある追跡番号で運送会社のメールと結べる（OCN・アイリス・楽天ショップ・GEKIROCK・ユニクロ・Locca・TikTok・レンズアップル）。Amazon だけは結べない
- 運送会社内: 送り状番号で 予定→配達中→不在→再配達→完了 を結べる
