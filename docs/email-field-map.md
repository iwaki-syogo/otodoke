# メール項目マップ（評価セット `fixtures/anonymized/`）

抽出器（`src/lib/extract/`）を作るための下調べ。実メール 341 通を `scripts/anonymize.py` で匿名化した評価セットを読み、
「どの項目が、どのメールの、どこに、どんな言い回しで書かれているか」をまとめた。

- 抜粋はすべて匿名化後の文面。氏名は「山田太郎」、住所は「〒100-0001 東京都千代田区千代田1-1 サンプルマンション101」、
  電話は 090-0000-0000、注文番号・追跡番号は同じ形の偽番号（この文書ではさらに `N` で伏せた）
- 「本文」は text/plain、「HTML」は text/html をテキスト化したもの。`.txt` サイドカーは本文（本文が無いときだけ HTML 由来）、
  `.json` サイドカーはデモ用ローダー向けに `file, source, stage, message_id, date, from, from_name, subject, text, html` を持つ
- ファイル名の日付は Date ヘッダーを日本時間に直した日付
- 件数は 2026-11-02 時点の評価セットのもの

| 項目 | 場所と書き方 |
|---|---|
| 注文番号 | 本文: `注文番号` の次の行に `NNN-NNNNNNN-NNNNNNN`。HTML では `注文番号 ‫NNN-…` と番号の直前に不可視の RTL 記号（U+202B）が入る。配達済みの一部は件名にも `注文番号 NNN-…` / `注文‎#NNN-…`（LRM 入り） |

## Design notes for the extractor

### 確実に取れるもの（本文だけで足りる）

- **注文番号**: Amazon（`注文番号` 次行）、楽天、OCN、レンズアップル、アイリス、GEKIROCK、ユニクロ、TikTok。ラベルの後ろが「同じ行・コロン」「次の行」「区切り無し」「`=`」の 4 通りあるので、ラベル＋次の行までを見る
- **追跡番号**: 運送会社と店の発送メール。形は `N×12` か `NNNN-NNNN-NNNN`（ヤマト・日本郵便）。同じ荷物でもメールによって区切りの有無が変わるので、比較は数字だけにしてから行う。運送会社はラベルの近くに書いてある（`運送便` `配送会社` `【配送業者】` `■佐川急便`）か、送信元のドメインで決まる
- **配達予定日（運送会社）**: ヤマトは `【M月D日(曜) …】`、佐川は `YYYY/MM/DD（曜）`、日本郵便は `M月D日(曜)`。ヤマト・日本郵便は年が無いので、メールの日付から年を補う（年末年始は翌年に繰り上げ）
- **時間帯**: `時間帯希望なし` / `時間指定なし` / `午前中` / `18時～20時` / `19〜21時` / `19:00〜21:00` / `5:00～13:00`。区切りが `～`（全角チルダ）・`〜`（波ダッシュ）・`-` で揺れる
- **配達完了**: ヤマト `お届け完了日時`、佐川 `お届け完了日時`、Amazon は件名 `配達済み` と `本日お届け済み`
- **品名・数量・価格**: Amazon の注文・発送（本文の `* ` 行が省略なしの品名）、楽天 order@、OCN、レンズアップル、アイリス、GEKIROCK、TikTok

### HTML が要るもの

- Amazon 定期おトク便「ご登録」の到着予定と頻度（本文に無い）
- Amazon 配達済みの配達写真（`<img>` だけ）
- ヤマト「お荷物お届けのご案内」の `受取方法 ： 対面での配達を希望`、郵便受け通知の `置き配で受け取り可能です。`
- TikTok Shop は 4 通とも HTML だけ
- Amazon の状態は本文の冒頭 1 行で決まるが、進捗表示で決めたいなら HTML の `[完了済み]` / `[保留中]`
- 注意: HTML の Amazon 注文番号の前には U+202B、件名の `注文‎#` には U+200E が入る。正規表現の前に不可視文字（U+200B–U+200F、U+202A–U+202E、U+2066–U+2069、U+034F、U+00AD）を消す

### たいてい無いもの

- **Amazon の運送会社と追跡番号**（0 / 240）。Amazon の荷物と運送会社のメールは注文番号では結べない。結ぶなら「運送会社メールの差出人が Amazon」「配達予定日が一致」「同じ日に配達中」の弱い手がかりしか無いので、`needs_review` にする
- **運送会社メールの注文番号・品名**（ヤマト・佐川・日本郵便は 0）。品名はヤマトの分類名だけ
- **配達予定の年**（ヤマト・日本郵便・Amazon 定期・アイリスの注文日）
- **Amazon の配達予定の絶対日付**。`本日` / `明日` / `木曜日` が 9 割で、メールの送信日時から計算する。Date は UTC なので **JST に直してから**「本日」を決める（Amazon 240 通中 73 通は UTC と JST で日付が変わる。評価セットのファイル名の日付は JST）
- **置き配の実際の指定**。「置き配できます」という案内文は多い（ヤマトほぼ全通、Amazon 配達中 59 通、佐川の定型文）が、実際に指定された受け取り方が書いてあるのは少ない:
  - Amazon: 配達済み 48 通中、`直接手渡しました` 2 通・`宅配ボックスに配達しました` 1 通だけ
  - ヤマト: `（受取方法：玄関ドア前／自宅宅配ボックス）`、`■受取ご希望場所：…`、`対面での配達を希望` が計 8 通
  - 佐川: `■配達指定場所` が 4 通（対面 3・玄関前 1）
  - 「置き配可能」「置き配指定可能」は指定ではないので、受け取り方の判定に使わない（`置き配` の語の有無だけで判定すると誤る）
- **返金**（金額付きの返金通知は 0。Amazon 取消は `請求は行われていません`）
- **ショップの注文メールの配達予定**（楽天・レンズアップル・アイリス・OCN は無いか、時間帯だけ）

### 名寄せ（同じ荷物か）の手がかり

- 店内: 注文番号で 注文→発送→配達中→配達済み を結べる（評価セットでも偽番号は全メールで一貫させてある）
- 店→運送会社: 店の発送メールにある追跡番号で運送会社のメールと結べる（OCN・アイリス・楽天ショップ・GEKIROCK・ユニクロ・Locca・TikTok・レンズアップル）。Amazon だけは結べない
- 運送会社内: 送り状番号で 予定→配達中→不在→再配達→完了 を結べる
